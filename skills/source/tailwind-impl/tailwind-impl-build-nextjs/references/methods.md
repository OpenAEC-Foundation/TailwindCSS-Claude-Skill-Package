# Methods : Tailwind CSS in Next.js

Per-router, per-version install walkthroughs. Each section is
self-contained.

## Method 1 : Tailwind v4 + App Router (Recommended for New Projects)

### Step 1 : scaffold the Next.js app

```bash
npx create-next-app@latest my-app --typescript --eslint --app
cd my-app
```

The `--app` flag selects the App Router. The generated `app/layout.tsx`
already contains an `import "./globals.css";` line; reuse it.

### Step 2 : install Tailwind v4 + PostCSS plugin

```bash
npm install tailwindcss @tailwindcss/postcss postcss
```

Three packages only. v4 does NOT require `autoprefixer` or
`postcss-import` ; both are built into the Oxide engine inside
`@tailwindcss/postcss`.

### Step 3 : write `postcss.config.mjs`

Create at project root :

```js
const config = {
  plugins: {
    "@tailwindcss/postcss": {},
  },
};
export default config;
```

The `.mjs` extension is required because Next.js reads the file as ESM.
`.js` works only if `"type": "module"` is set in `package.json`.

### Step 4 : replace `app/globals.css` contents

```css
@import "tailwindcss";
```

That single line replaces every v3 directive. Delete any pre-existing
`@tailwind base;`, `@tailwind components;`, `@tailwind utilities;` lines
from the create-next-app template.

### Step 5 : verify the import in `app/layout.tsx`

```tsx
import "./globals.css";

export const metadata = { title: "My App" };

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

### Step 6 : run

```bash
npm run dev
```

Add `className="text-3xl font-bold underline"` to any heading. If the
text is large, bold, and underlined, the install is complete.

## Method 2 : Tailwind v4 + Pages Router

### Step 1 : scaffold

```bash
npx create-next-app@latest my-app --typescript --eslint --no-app
cd my-app
```

The `--no-app` flag selects the Pages Router. The template provides
`styles/globals.css` and imports it in `pages/_app.tsx`.

### Steps 2 and 3 : identical to Method 1

`npm install tailwindcss @tailwindcss/postcss postcss` and write
`postcss.config.mjs` exactly as above.

### Step 4 : replace `styles/globals.css` contents

```css
@import "tailwindcss";
```

### Step 5 : verify the import in `pages/_app.tsx`

```tsx
import "@/styles/globals.css";
import type { AppProps } from "next/app";

export default function App({ Component, pageProps }: AppProps) {
  return <Component {...pageProps} />;
}
```

The `@/` alias resolves to `src/` if you opted in, otherwise to project
root. Use whichever path the template generated.

### Step 6 : run

`npm run dev`, same verification as Method 1.

## Method 3 : Tailwind v3 + App Router

Pinned to v3 explicitly because v3 is no longer the default install
target.

### Step 1 : scaffold (same as Method 1)

```bash
npx create-next-app@latest my-app --typescript --eslint --app
cd my-app
```

### Step 2 : install v3 dependencies

```bash
npm install -D tailwindcss@3 postcss autoprefixer
npx tailwindcss init -p
```

The `-p` flag generates `postcss.config.js` alongside
`tailwind.config.js` in one step. The pinned `tailwindcss@3` is critical
because `npm install -D tailwindcss` without a version installs v4 and
breaks the v3 directives.

### Step 3 : populate the content array

`tailwind.config.js` :

```js
/** @type {import('tailwindcss').Config} */
module.exports = {
  content: [
    "./app/**/*.{js,ts,jsx,tsx,mdx}",
    "./pages/**/*.{js,ts,jsx,tsx,mdx}",
    "./components/**/*.{js,ts,jsx,tsx,mdx}",
    "./src/**/*.{js,ts,jsx,tsx,mdx}",
  ],
  theme: { extend: {} },
  plugins: [],
};
```

List every directory that contains JSX or TSX. Forget one and its
utilities will silently never compile.

### Step 4 : confirm `postcss.config.js`

```js
module.exports = {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
};
```

Generated by `init -p` ; verify it exists.

### Step 5 : replace `app/globals.css` contents

```css
@tailwind base;
@tailwind components;
@tailwind utilities;
```

Order matters : `base` first (resets and preflight), then `components`
(multi-utility component classes), then `utilities` (single-purpose).

### Step 6 : verify import in `app/layout.tsx`

```tsx
import "./globals.css";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

### Step 7 : run

`npm run dev`. Same heading check.

## Method 5 : Wire next/font/google (v4 App Router)

### Step 1 : import the font in the root layout

```tsx
// app/layout.tsx
import { Inter } from "next/font/google";

const inter = Inter({
  subsets: ["latin"],
  variable: "--font-inter",
  display: "swap",
});
```

`variable` declares the CSS custom property name next/font will inject
on the element you apply `inter.variable` to. Use kebab-case prefixed
with `--font-`.

### Step 2 : apply the className on `<html>` or `<body>`

```tsx
return (
  <html lang="en" className={inter.variable}>
    <body className="font-sans">{children}</body>
  </html>
);
```

This emits `<html style="--font-inter: 'Inter', 'Inter Fallback';">`.

### Step 3 : declare the token in `@theme inline`

`app/globals.css` :

```css
@import "tailwindcss";

@theme inline {
  --font-sans: var(--font-inter), ui-sans-serif, system-ui, sans-serif;
}
```

ALWAYS `@theme inline` (NOT bare `@theme`). Bare `@theme` resolves the
`var(...)` reference at build time, when next/font has not yet run, and
emits the resolved-to-empty literal. `@theme inline` emits the literal
`var(...)` text, which the browser resolves at runtime against
next/font's injected custom property.

### Step 4 : confirm with DevTools

Inspect the computed `font-family` of a `font-sans` element. The first
entry should be `Inter`. If it falls back to `ui-sans-serif`, the
className did not reach the element.

## Method 6 : Wire next/font/google (v3 App Router)

`app/layout.tsx` identical to Method 5 steps 1 and 2.

`tailwind.config.js` :

```js
module.exports = {
  content: [/* unchanged */],
  theme: {
    extend: {
      fontFamily: {
        sans: ["var(--font-inter)", "ui-sans-serif", "system-ui", "sans-serif"],
      },
    },
  },
};
```

v3 reads JS config at build time but the array contains a literal
`"var(--font-inter)"` string, so the generated CSS contains the
`var(...)` reference verbatim. Same runtime resolution.

## Method 7 : Multiple Font Families

Wire each family the same way. v4 example with Inter (body) and JetBrains
Mono (code) :

```tsx
import { Inter, JetBrains_Mono } from "next/font/google";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });
const mono = JetBrains_Mono({ subsets: ["latin"], variable: "--font-mono" });

return (
  <html lang="en" className={`${inter.variable} ${mono.variable}`}>
    <body>{children}</body>
  </html>
);
```

```css
@import "tailwindcss";

@theme inline {
  --font-sans: var(--font-inter), ui-sans-serif, system-ui, sans-serif;
  --font-mono: var(--font-mono), ui-monospace, monospace;
}
```

Now `font-sans` resolves to Inter and `font-mono` resolves to JetBrains
Mono.

## Method 8 : Disable Turbopack Selectively

`package.json` :

```json
{
  "scripts": {
    "dev": "next dev",
    "dev:turbo": "next dev --turbo",
    "build": "next build"
  }
}
```

Default to webpack `next dev` until issue 19825 has a confirmed-fixed
version of `tailwindcss` and Next.js paired in your lockfile. Run
`dev:turbo` only when you actively want to test Turbopack compatibility.

## Method 9 : Add `@source` for Component Libraries

When importing a shared UI library from `node_modules` (for example a
private design system), Tailwind v4 will NOT scan it by default. Add :

```css
@import "tailwindcss";
@source "../node_modules/@my-org/ui-lib";
```

v3 equivalent in `tailwind.config.js` :

```js
content: [
  "./app/**/*.{js,ts,jsx,tsx,mdx}",
  "./node_modules/@my-org/ui-lib/**/*.{js,ts,jsx,tsx}",
],
```

## Production Build Verification

```bash
npm run build
```

Inspect `.next/static/css/*.css`. The file should contain :

- The selectors you use (`grep -c "text-3xl" .next/static/css/*.css`
  should be > 0).
- No unused utilities (purged at build).
- If using next/font : `--font-inter` variable inside `:root` or the
  body selector, and `font-family: var(--font-inter), ...` on the
  `font-sans` selector.

If a selector is missing : either the file containing the class is not
scanned (content glob or `@source` problem), or Turbopack incremental
scanning dropped it (Method 8).
